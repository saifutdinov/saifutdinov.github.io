Thread
Go · E2EE chat
End-to-end encrypted chat for family and close friends that you run on your own server: one Go binary with SQLite, a Preact PWA, invite-only access, messages, media, 1:1 and group calls. The server stores only ciphertext. Open source (AGPL-3.0).
What it demonstrates
  • Own E2EE design on standard WebCrypto primitives (ECDH/ECDSA P-256, AES-256-GCM, HKDF) with device approval and safety codes — and its limits stated openly (not independently audited).
  • Real-time core in Go: WebSocket hub, Web Push with ciphertext payloads, 1:1 WebRTC calls with sealed signalling and TURN, group calls through LiveKit with end-to-end encrypted frames.
  • Small-server engineering: runs on a 1 GB VPS — SQLite (WAL), argon2id passwords, SSRF-guarded link previews, encrypted daily backups to S3, Prometheus metrics.
  • Decisions recorded as ADRs; Go and TypeScript test suites, real-browser call tests and CI.

pdf-formatter
Go · PDF editor
A PDF editor that runs on your computer and edits existing documents surgically: the touched block is rewritten inside the page's content stream and the rest of the page stays byte-for-byte identical. Built on its own Go PDF library (ISO 32000-1); downloadable builds for macOS, Windows and Linux. Open source (AGPL-3.0).
What it demonstrates
  • Hand-written PDF library in Go: parser and writer, xref/object streams, filters, encryption (standard handler, revisions 2–6), fonts and CMaps, TrueType embedding, content-stream rewriting, forms and bookmarks — about 21k lines of Go with 24 test files.
  • Non-destructive model: the source file is never changed; a document is the source plus an operation log, the new PDF is a pure function of both, and undo removes the last operation.
  • Documents never leave the machine: the server listens on 127.0.0.1 only, and the interface and fonts are embedded into one executable per platform.
  • Shipped as releases (macOS .dmg, Windows and Linux builds); output files are verified with qpdf in the test image.
True Vision
Go + Vue · live streaming
Private repo
Private live streaming for games (sim racing first): the streamer goes live from OBS via WHIP or straight from the browser, viewers watch in the browser over WebRTC with sub-second latency. The owner decides who can watch — password, invite link, any signed-in account, or only themselves.
What it demonstrates
  • Signalling-only Go backend (Connect-RPC API, SQLite): video never passes through Go — it flows over UDP between OBS, MediaMTX and browsers.
  • Access control that is re-checked live: one decision function at connect time, a one-time ticket plus a MediaMTX hook that re-verifies, and a ~6-second reconciliation loop that kicks viewers whose access was revoked.
  • Release pipeline that backs up the database, proves the backup by restoring it, and only then migrates and swaps the container; a failed check stops the release and the old version keeps serving.
  • protobuf/buf-generated API, Go tests and real-browser E2E against a real MediaMTX.

Shorts Studio
Go · video editor & publishing (local)
Local-first app for one operator that turns source videos into reviewed vertical short-form videos (9:16) with commentary, voice-over and subtitles, and prepares them for YouTube Shorts and Instagram Reels (optional YouTube upload through the official API — tested against fakes only — and an export package for Instagram). Nothing is published without an explicit approval step.
What it demonstrates
  • Full pipeline that works offline with no API keys: import → rights check → metadata → transcript (local speech-to-text) → events and script → subtitles → voice-over → 9:16 render → review → approval → export.
  • Local AI where it helps: a local vision-language model proposes events from frames and transcript; cloud analysis is optional and off by default.
  • Resumable job model: every stage has a state, logs and a retry that does not repeat the expensive stages; interrupted jobs are marked and resumable by retry.

Ant Colony
Go · real-time game server
Private repo
Browser ant-colony simulation. The player doesn't control the ants — they watch a colony forage, raise brood, dig tunnels and rooms, relocate its base, and go to war with neighboring colonies. All simulation logic runs on an authoritative Go server; the browser only renders and sends commands.
What it demonstrates
  • Single-goroutine authoritative game engine — no per-entity goroutines, no world mutex; state changes only through commands, immutable snapshots handed outward.
  • WebSocket protocol with snapshot + delta frames and compressed chunk streaming for a live, persistent world.
  • SQLite persistence with versioned snapshots plus a Redis hot cache — the simulation survives server restarts.
  • Deterministic seeded RNG, A*/flow-field navigation, and a full test suite run with -race.
go-invoices-api
Go · Clean Architecture
Payment Reconciliation Service: matches incoming payments against issued invoices, computes invoice status, and keeps a full audit log. Built on Clean Architecture with PostgreSQL transactions and row-level locking.
What it demonstrates
  • Idempotent payment processing under concurrent access — row-level locking (SELECT ... FOR UPDATE) around every reconciliation transaction.
  • Invoice status computed from payment allocations (unmatched / partially paid / paid / overpaid), with a full audit trail of every discrepancy.
  • A small custom scheduler (`chronos`) for background reconciliation instead of pulling in a message broker.
  • Money stored as integer minor units to avoid floating-point errors in financial calculations.
